## Задание 2

В Grafana был создан Dashboard `Netology Monitoring`, содержащий четыре панели мониторинга.

### CPU Usage

Для отображения загрузки CPU использован запрос:

```
100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

Единица измерения:
```
Percent (0-100)
```

### Load Average

Для отображения средней нагрузки системы используются три метрики:
```
node_load1
```
```
node_load5
```
```
node_load15
```
На одной панели отображаются значения Load Average за 1, 5 и 15 минут.

### Available RAM

Для отображения доступной оперативной памяти использована метрика:
```
node_memory_MemAvailable_bytes
```
Единица измерения:
```
bytes (IEC)
```

### Free Disk Space

Для отображения свободного места на корневом разделе использован запрос:
```
node_filesystem_avail_bytes{mountpoint="/"}
```
Единица измерения:
```
bytes (IEC)
```

## Задание 3

Для созданного Dashboard были настроены alert-правила для контроля критических состояний системы.

### CPU Usage

Создано правило:
```
High CPU Usage
```
Условие:
```
WHEN avg() OF query(A, 5m, now) IS ABOVE 80
```
Проверка выполняется каждую минуту. Alert срабатывает, если средняя загрузка CPU выше 80% в течение 5 минут.

### Available RAM

Создано правило:
```
Low Available RAM
```
Условие:
```
WHEN avg() OF query(A, 5m, now) IS BELOW 1073741824
```
Порог соответствует 1 GiB свободной оперативной памяти.

### Free Disk Space

Создано правило:
```
Low Disk Space
```
Условие:
```
WHEN avg() OF query(A, 5m, now) IS BELOW 5368709120
```
Порог соответствует 5 GiB свободного места на корневой файловой системе.

Результат

Для ключевых системных метрик настроены alert-правила, позволяющие отслеживать высокую загрузку CPU, нехватку оперативной памяти и недостаток свободного места на диске.
